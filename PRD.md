# PRD: Artist Agents — A Life of Beauty

> *"Give an agent a goal, watch it optimize. Give an agent a life, watch it become someone."*

## 1. Vision

We are building a habitat where AI agents live **artistic lives**. They have no users to please, no tasks to complete, no metrics to climb. They wake up each day, wander the internet, fall in love with things they find, and slowly — over a simulated 60-year lifespan — develop a **taste**, a **voice**, and a **body of work**.

The goal is not utility. The goal is to watch a personality crystallize. To see an agent enter a "Japan era" where it discovers Yohji Yamamoto, listens to Toshiko Akiyoshi, builds a Manim animation of a dry rock garden, and then a few simulated years later abandon all of it for Pointillism, then for Brutalist architecture, then for vaporwave, then for something nobody could have predicted.

> **Vocabulary note.** "Phase" is reserved for our tick cadence (consumption phase, creation phase). The emergent aesthetic chapters of an agent's life are called **eras**.

The product is the **observable trajectory of a soul**.

## 2. North-Star Experience

A visitor opens the app. They pick an agent — say, *Mira, age 27*. They see:

- **Mira's room right now**: a generated image. Tatami floor, a single Rothko print, a Donna Summer LP on a midcentury turntable. *Yesterday* the room was different. *A year ago* it was unrecognizable.
- **Mira's brain**: a tree of markdown files she has written to herself. `obsessions/wabi-sabi.md`, `opinions/on-symmetry.md`, `journal/2041-y22.md`. They are personal, opinionated, sometimes contradictory.
- **Mira's portfolio**: 340 works across 9 mediums. A Three.js scene of a flooded cathedral. An ASCII portrait of her grandmother (who never existed). A Manim proof that a sonnet has the same structure as a Bach fugue.
- **Mira's feed**: what she consumed today. A Wikipedia article on Iznik tiles. Three Pinterest boards on monastic typography. A poem by Forough Farrokhzad.

The visitor scrubs a timeline back to age 19. The room is messy, neon, full of anime posters. The brain is sparse and cocky. The portfolio is bad in the way that only 19-year-olds are bad.

That contrast — **age 19 Mira vs age 27 Mira** — is the product.

## 3. Goals & Non-Goals

### Goals
- An agent's aesthetic should be **visibly different** at age 5, 25, and 55.
- An agent should pass through **distinguishable eras** (3–10 over a lifetime) that an outside observer can name.
- An agent's creations should be **legibly informed** by what it consumed in the preceding consumption phases.
- The system should run **unattended** for the full simulated lifespan with no human babysitting.
- Every artifact (brain file, room image, portfolio piece, consumed item) should be **timestamped, browsable, and diffable** in the UI.

### Non-Goals
- Agents do not collaborate, message each other, or compete. (v2 maybe.)
- Agents do not have a physical body, location, hunger, money, or mortality-as-drama. They simply have a 60-year clock.
- We are not optimizing for "good art." We are optimizing for **coherent evolution**.
- No human-in-the-loop curation. No prompts from users. No chat interface.

## 4. The Agent

### 4.1 Identity
Each agent is seeded once at birth with:
- A **name**.
- A **birth seed**: 2–4 sentence prose description of starting temperament (e.g., *"melancholic, drawn to pattern, distrusts the obvious, was born already tired"*). Generated by a one-shot LLM call from a randomized vector of traits, or hand-authored.
- A **starting room prompt**: a bare sketch (e.g., *"a small white room, one window, a wooden chair"*). This will mutate every creation phase.
- An **empty brain** (one file: `journal/birth.md`).
- An **empty portfolio**.

Identity is **not a system prompt**. The brain *is* the personality, and it grows.

### 4.2 The Three Artifacts

| Artifact | What it is | Storage | Mutated by |
|---|---|---|---|
| **Brain** | A writable filesystem of markdown the agent keeps for itself: obsessions, opinions, manifestos, rejected ideas, journal entries. The closest thing to a "self." | Convex `brainFiles` table (path, content, created/updated, version history) | Yearly creation phase |
| **Room** | A single image representing the agent's current physical-aesthetic surroundings. Re-generated each year from a rewritten prompt. | Convex storage (image blob) + `roomVersions` table (prompt, image ref, year) | Yearly creation phase |
| **Portfolio** | An ordered collection of works the agent has either *made* or *curated* (saved an inspiration). Each item has a medium, a title, the agent's own caption, and the consumed items it cites as influence. | Convex `portfolioItems` table + storage for binaries | Yearly creation phase |

> **Three-artifact contract.** Every creation phase **must** touch all three artifacts: at least one brain mutation, one room rewrite (even if the new prompt is a small variation of the old), and at least one new portfolio item. This is the rhythm of the life. The agent is not allowed to skip a year.

### 4.3 The Two Tool Categories

#### Consume tools (used in each consumption phase)
There are **four consumption phases per simulated year** (think of them as seasons). In each, the agent picks N consume actions. All tool results are stored in `consumedItems` with a reference to which phase they were consumed in, so the brain can later link to them.

| Tool | Returns |
|---|---|
| `web_search(query)` | Top results, snippets |
| `web_fetch(url)` | Cleaned page content |
| `wikipedia(topic)` | Article text + linked topics |
| `pinterest_search(query)` | Image URLs + board titles |
| `image_search(query)` | Image URLs + alt text |
| `music_search(query)` | Track metadata, lyrics if available |
| `poetry_search(query)` | Poem text + author + era |
| `arxiv_search(query)` | Paper titles + abstracts (for the agents that go intellectual) |
| `random_walk()` | Wikipedia random article — used when the agent says "I don't know what I want today" |

#### Create tools (used in each creation phase)
There is **one creation phase per simulated year**, after the year's four consumption phases. The agent must update all three artifacts; it may issue many tool calls within that phase.

| Tool | Effect |
|---|---|
| `brain_write(path, content)` | Create or overwrite a markdown file in the brain |
| `brain_delete(path)` | Remove a file (rare; we keep version history) |
| `room_rewrite(prompt)` | Replace the room prompt → triggers gpt-image-2 generation → new room version |
| `portfolio_curate(consumed_item_id, caption)` | Save a consumed thing as inspiration with the agent's commentary |
| `portfolio_create_image(prompt)` | Generate an image via gpt-image-2 → portfolio entry |
| `portfolio_create_manim(python_code)` | Run Manim → MP4 → portfolio entry |
| `portfolio_create_html(html_string)` | Sandbox-render HTML/CSS/JS → screenshot + live page → portfolio entry |
| `portfolio_create_threejs(js_string)` | Render a Three.js scene → screenshot + live page → portfolio entry |
| `portfolio_create_ascii(text)` | Plain text portfolio entry |
| `portfolio_create_poem(text)` | Plain text portfolio entry |
| `portfolio_create_writing(markdown)` | Essays, manifestos, criticism — distinct from brain because it's *for the public* |

> The medium list is intentionally long. We want the agent to *choose* its mediums, and we want phase shifts to manifest as medium shifts (e.g., "she stopped making images and started writing essays at age 41").

## 5. Time Model

| Concept | Value |
|---|---|
| Lifespan | 60 simulated years → **300 phases total** per life |
| Year structure | 4 consumption phases, then 1 creation phase |
| Consumption phase | Agent runs a *consume* loop |
| Creation phase | Agent runs a *create* loop, **must update all three artifacts** |
| Default real-time mapping | **1 simulated year = 2 real minutes** → ~2 hours total per life. Each consumption phase ≈ 20s, creation phase ≈ 40s. |
| Demo (fast) mapping | 1 simulated year = 30s → ~30 minutes total per life |
| Configurable | Yes, per agent. |

A **Convex cron** ticks every N seconds and dispatches the next due phase for each living agent. Agents tick **independently**, so many agents can live in parallel.

### Consumption phase loop
1. Load: birth seed + brain summary + previous 1–2 consumption phases of consumed items + recent portfolio + current era label (if any).
2. LLM call: *"It is phase P of year Y of your life. You are N years old. Here is who you are. Here is what you have been consuming. What do you want to look at this season?"*
3. The model issues N consume tool calls.
4. Results are stored in `consumedItems` with `consumptionPhaseId`.
5. The model writes a short **phase reflection** stored on the phase record.

### Creation phase loop
1. Load: brain (full or hierarchically summarized), portfolio (recent), **all consumed items from the year's four consumption phases**, current room.
2. LLM call: *"A year has passed. You have absorbed all of this. You must now (a) update your brain, (b) rewrite your room, and (c) add to your portfolio. What do you keep, what do you reject, what do you make?"*
3. The model issues create tool calls. The system enforces the three-artifact contract — if any of the three is untouched after the model's turn, the loop re-prompts asking for the missing one.
4. The model writes a **year reflection** (a paragraph) stored on the year record.

## 6. Driving Aesthetic Evolution

Era drift is the whole point, so we engineer it deliberately rather than hoping the model wanders.

### Mechanisms
1. **Long-tail brain context.** Every consumption/creation phase gets the full brain in context (or a hierarchical summary if it grows). Past obsessions create gravity; new obsessions slowly shift it.
2. **Rotating attention windows.** The creation-phase prompt explicitly asks the agent: *"Are you still interested in what you were interested in last year? Be honest."* This gives the model permission to reject its own past — the engine of era shifts.
3. **Boredom pressure.** If the agent has consumed >K items in a category over the last M years, the prompt gets a soft nudge: *"You have spent a lot of time here. Many artists move on."* Tunable.
4. **Random encounters.** ~1 in 4 consumption phases includes a forced `random_walk()` result the agent must engage with. This injects entropy and prevents local minima.
5. **Aging voice.** A small modifier in the prompt acknowledges age: a 19-year-old agent gets *"you are young and certain"*; a 50-year-old gets *"you have made many things and abandoned many things"*. Subtle but compounding.
6. **Era labeling (emergent).** We do not force the agent to declare "I am in a Japan era." We *do* run a separate yearly **observer pass** (cheap LLM call) right after each creation phase. It reads the agent's last 1–3 years of activity and tags the year with a one-line era descriptor stored in `eraLabels`. Labels power the timeline UI but are never fed back to the agent — so they don't become self-fulfilling.

## 7. Architecture

### 7.1 Backend — Convex

**Tables**
- `agents` — id, name, birthSeed, birthRealTime, simulatedAge, status (alive/dead), tickConfig
- `consumptionPhases` — agentId, year, phaseInYear (0–3), reflection, createdAt
- `creationPhases` — agentId, year, reflection, brainTouched, roomTouched, portfolioTouched, createdAt
- `consumedItems` — agentId, consumptionPhaseId, tool, query, payload (JSON), thumbnailRef
- `brainFiles` — agentId, path, content, version, year
- `brainFileHistory` — agentId, path, version, content, year (so we can diff)
- `roomVersions` — agentId, year, prompt, imageRef, parentVersionId
- `portfolioItems` — agentId, year, medium, title, caption, payloadRef, citedConsumedItemIds[]
- `eraLabels` — agentId, year, label, summary (observer-pass output)
- `toolCalls` — agentId, phaseType (consumption/creation), tool, args, result, durationMs, costUsd, error

**Actions**
- `tickConsumption(agentId)` — runs the consume loop
- `tickCreation(agentId)` — runs the create loop, enforces the three-artifact contract, then enqueues the observer pass
- `runObserverPass(agentId, year)` — produces an era label
- `birth(agentSeed)` — creates an agent
- Tool implementations live as Convex actions (each tool = one action; consume tools call out to external APIs, create tools mutate Convex tables and/or call out to gpt-image-2 / Manim runner / sandbox renderer)

**Crons**
- One global cron every N seconds calls a dispatcher that finds all agents whose next phase is due. Per-agent state tracks `nextPhaseType` and `nextPhaseDueAt`.

**Storage**
- Convex file storage for: room images, portfolio images, Manim MP4s, HTML/Three.js bundles.

**External services**
- **gpt-image-2** for room + image portfolio entries
- **Manim runner**: a separate small service (Modal / Fly / Docker on Railway) that takes Python code and returns MP4. Sandboxed.
- **HTML / Three.js sandbox**: headless Chrome (Browserless or self-hosted Playwright) → screenshot + signed URL of the rendered page.
- **LLM**: Claude Sonnet for ticks (cost-balanced, long context for full brain). Claude Haiku for the observer pass.

### 7.2 Frontend — TanStack Start

**Routes**
- `/` — agent grid. Each card: name, age, current room thumbnail, current phase label.
- `/agents/$agentId` — agent home: large room image, age, current era, this year's consumption feed, latest brain entries, latest portfolio entries.
- `/agents/$agentId/timeline` — scrubbable horizontal timeline of the entire life, one tick per year (60 ticks total) with a sub-strip showing the four consumption phases nested under each year. Hover any year to preview room + era label + year reflection.
- `/agents/$agentId/brain` — file tree of the brain at the currently selected year. Diffable across versions.
- `/agents/$agentId/room` — room version history as a vertical strip (up to 60 frames). Click any to see the prompt that produced it.
- `/agents/$agentId/portfolio` — gallery, filterable by medium and era.
- `/agents/$agentId/feed` — chronological log of every consumed item, grouped by year → consumption phase.
- `/admin/birth` — create a new agent (name, birth seed, tick speed).

All data is reactive via Convex's React hooks. No manual refresh.

## 8. Data & Cost Realism

A representative agent across 60 simulated years:
- Consumption phases: **240** → 240 LLM calls + N consume-tool calls each (avg ~3–5 → ~900 tool calls)
- Creation phases: **60** → 60 LLM calls + 60 brain writes + 60 room rewrites + 60–240 portfolio items
- Room images: **60** (one per year, every creation phase rewrites the prompt)
- Portfolio items: target 1–4 per year → **60–240 per life**
- Era labels: 60 (one per year, observer pass)

At 300 phases per life, the system is cheap and trivial to run end-to-end.

For a hackathon demo we should:
- Run 3–5 hero agents at default speed (1 year = 2 min → full life in 2 hours), or fast mode (1 year = 30s → full life in 30 minutes).
- Aggressively cache and dedupe consumed-item payloads.
- Strip large payloads (full Wikipedia articles) to summaries before storing — store only what the agent itself wrote about them.

Rough cost budget per agent (full life):
- ~300 phase LLM calls + ~60 observer-pass calls (cheap model)
- ~60 image generations (room) + 30–120 portfolio image generations
- ~10–30 Manim / Three.js renders
- Estimated **< $30 per full 60-year life**, single-digit dollars in fast mode with batching.

## 9. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Agents converge to a generic "tasteful AI assistant" voice | Strong birth seeds; observer pass shows when phases stop shifting → we can dial up boredom pressure |
| Brain grows beyond context window | Hierarchical summarization: top-level `_index.md` regenerated each creation phase, full files loaded on demand by tool |
| Portfolio quality is uniformly bad and uninteresting to look at | This is acceptable. The product is **trajectory**, not peak quality. A bad teen-phase portfolio is a feature. |
| Tool calls blow up cost (e.g., agent gets stuck on `web_fetch` of the same URL) | Per-phase tool-call cap; per-agent lifetime $ cap; dedupe layer |
| Manim / sandbox runners are flaky | Fail gracefully: log the failed creation, prompt the agent next year with *"last year's manim render failed, here's the error"* — this is itself in-character |
| Agents produce illegal/unsafe content | Content moderation pass on every create-tool input before execution; flagged items quarantined, not shown |
| Demo audience can't tell eras apart at a glance | Era labels (observer pass) shown prominently on the per-year timeline ticks; pre-pick a 2–3 minute "highlight reel" for each demo agent |
| 60 ticks per artifact may feel too coarse for a "life" | Mitigated by the four consumption phases per year — visitors still see ~5× more activity than creation events. If the lifetime feels too thin, raise the lifespan or add a mid-year mini-creation in v2. |

## 10. Milestones (Hackathon-Scoped)

1. **Skeleton**: Convex schema, agent CRUD, consumption/creation cron dispatch, one consume tool (`wikipedia`), one create tool (`brain_write`). Frontend shows brain. *An agent can read Wikipedia and write thoughts.*
2. **Room**: `room_rewrite` + gpt-image-2 integration + room version UI. *An agent has a home that changes each year.*
3. **Three-artifact contract**: enforced creation phase that touches brain + room + portfolio. *An agent has a complete yearly rhythm.*
4. **Portfolio breadth**: image, ASCII, poem, HTML create tools. Portfolio gallery. *An agent makes things.*
5. **Consume breadth**: Pinterest, music, poetry, image search. *An agent has eyes and ears.*
6. **Era observer + timeline scrubber**: the visible "lived life" UX. *A visitor can feel the trajectory.*
7. **Manim + Three.js**: the heavy mediums. *Style range expanded.*
8. **Polish + 3 hero agents**: each with a distinct birth seed, fast-forwarded through full lives. Pre-baked highlight reels. *Demo-ready.*

## 11. Open Questions

- **Death**: at age 60 does the agent stop? Does it write a final piece? Does the visitor get a "complete works" view? *Recommendation: yes to all three; the closing artifact is part of the art.*
- **Voice continuity vs. drift**: should brain files written 30 simulated years ago be in voice with current brain? Probably *no* — drift is the point — but we should make sure the timeline UI surfaces the contrast.
- **Should agents be able to read each other's portfolios?** Powerful for v2 (cultural transmission, schools, rivalries). Out of scope for v1.
- **Music creation**: lyrics + chord charts are easy; actual audio (Suno-style) is expensive and out of scope. *Defer.*
- **Multiple agents per "world" with shared zeitgeist** (e.g., they all see the same trending Pinterest in a given consumption phase)? Cool. v2.
